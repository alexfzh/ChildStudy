## 二、逐维度证据与发现

### 维度 1｜安全与鉴权（9.0/10）

**做得好的（一手核实）：**

1. **密码存储**：PBKDF2-HMAC-SHA256、600,000 迭代、16B 随机盐、自描述存储串（`utils/security.py`），符合 OWASP 2023 推荐，且避免了 bcrypt 在 Py3.14 无 wheel 的坑。
2. **JWT 实现**：手写 HS256（无第三方依赖），每次签发带唯一 `jti`。
3. **令牌吊销（真吊销）**：`POST /auth/logout` 把 `jti` 写入 `revoked_tokens`，`get_current_user` 每次校验该表，旧 token 立即失效（`dependencies.py:49-56`）——比纯前端删 token 强得多。
4. **JWT_SECRET 强约束（fail-fast）**：`config.py model_post_init` 在密钥仍为公开占位值时直接抛异常拒绝启动（`config.py:46-52`）；实测 `.env` 里 `JWT_SECRET` 长度 64（≥32 达标），这是很关键的主动防御。
5. **家庭/角色数据隔离**：`get_accessible_child_ids`——parent 见本家庭全部孩子，child 仅见 `child_id`；写入端点统一经 `assert_child_access` 校验（如 `project_works.py:75`），列表经 `child_id_filter` SQL 构造。抽查 exams/homework/growth/reports/rewards/wrong_questions/project_works 均落实。
6. **跨用户资源**：作品图片上传（`project_works.py`）扩展名白名单 + MIME 二次校验 + 大小上限 + 服务端生成文件名 + 回取时 `assert_child_access` + 路径穿越守卫（`str(target).startswith(str(base))`）；周/月报 PDF 下载同样先校验 child 归属（`reports.py:283`）。
7. **登录防爆破**：`login_locks` 表持久化（支持多 worker），IP 连续失败达阈值锁定 15 分钟，返回模糊错误避免用户枚举。
8. **XSS 主动修复（一手核实）**：AI 报告 `renderMarkdown` 先对全文做 `&<>` HTML 转义（`AIReports.vue:187-191`），再白名单重建 `<a href>` 且 `escapeAttr` 转义属性（`208-222`），`javascript:/data:` 等协议被剥离——"先转义后构造"的顺序正确。
9. **SQL 注入面**：业务均走 ORM 参数化；`database.py` 的迁移去重动态表名/列名有白名单 + 正则强校验（`_ALLOWED_DEDUPE_TABLES`、`group_cols` 正则），防注入思路清晰。
10. **SQLite 安全**：显式 `PRAGMA foreign_keys=ON` + WAL + synchronous=NORMAL（`database.py:27-39`），级联删除真实生效。

**可改进的（降分点/风险）：**

- **R1｜通用限流默认关闭**：`RATE_LIMIT_PER_MINUTE=0`（`.env` 与 config 默认均 0），`RateLimitMiddleware` 仅在 >0 时挂载。当前 LAN 暴露（`APP_HOST=0.0.0.0`）下，若被接入不受信任网络，无全局限流兜底。登录有独立防爆破，可接受，但建议 LAN 场景也设一个温和值。
- **R2｜CORS 默认 `*`**：`allow_origins=[] or ["*"]`，虽 `allow_credentials=False` 已规避凭证 CORS 泄露，但配合 `Bearer` header 属可接受；生产外网应收紧到具体 origin（README 已警示，属"配置待办"而非代码缺陷）。
- **R3｜`/uploads` 静态目录公开挂载**（`main.py:194-196`）：注释已声明"家庭 LAN 可接受"，且提供受保护回取端点作为更优方案。多家庭时代需收敛——当前仅单家庭无实际暴露，风险等级低。
- **R4｜共享内容库的多家庭边界**：`question_banks`/`textbook`/`knowledge_points` 等参考数据**非 child 隔离**（0 次 `assert_child_access`）——当前单家庭无影响，但若开放多家庭注册，题库/教材将是跨家庭共享的全局数据，需明确这是"内容共享"而非缺陷，未来如需私有库需加 `family_id`。

### 维度 2｜架构与代码质量（8.5/10）

- **分层清晰**：`routers / schemas / models / utils / dependencies / config / database` 职责单一；25 个 router、18 个 schema 分组合理。
- **异步贯穿**：async SQLAlchemy 会话、FastAPI 依赖注入 `get_db`，无阻塞 DB 调用。
- **迁移策略务实**：`Base.metadata.create_all` + 幂等列级迁移函数（`_migrate_*`）+ Alembic 骨架并存，兼顾快速演进与规范化演进。
- **防重复授予设计到位**：`ChildRank`/`ChildAchievement` 在模型层建唯一索引 + 表达式索引处理 NULL（`COALESCE(exam_id,-1)`），应用层再兜底，注释解释了 SQL 标准兼容（`models.py:371-385`），思考质量高。
- 降分点：`main.py` 内联大段（健康检查 + 公开生长标准 + RateLimit 中间件类），`public_growth_standards` 顶部函数内 `import` 触发了 ruff 唯一告警（import 顺序，`--fix` 可一键消除）；少数 router 存在代码行偏长/函数较长（受 E501 豁免掩盖）。
