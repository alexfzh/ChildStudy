# ChildStudy 系统独立审计报告（2026-09-03）

> 审计方式：独立、源码级、多维度。审计者不依赖第三方既有报告，结论均来自对 `backend/`（~1.89 万行业务代码）与 `frontend/`（~0.89 万行源码）的直接阅读与交叉验证。
> 审计范围：后端架构、鉴权与安全、前端代码与构建、数据层、功能完整度、性能与可维护性。
> 版本基线：后端 `1.7.3`（main.py / system.py 一致），前端 `1.7.3`（package.json）。

---

## 一、执行摘要

ChildStudy 是一个面向家庭场景的「儿童成长记录 + 学情分析」全栈应用，技术栈为 **FastAPI（异步 SQLAlchemy）+ Vue 3（Vite + Element Plus + ECharts）**，单仓库、SQLite 存储。整体工程质量明显**高于同类个人/家庭项目平均水平**：分层清晰、测试完备（pytest 168 passed）、安全基建设计到位（强哈希、JWT、数据隔离、登录防爆破）。

综合评分 **84 / 100（评级 B+，良好偏上）**。主要扣分点集中在少数可被利用的「默认配置风险」与个别功能性缺口，而非系统性缺陷。未发现严重级（Critical）漏洞，但存在 **1 项 High 级纵深防御缺口**与 **2 项 Medium 级功能性/前端风险**，均给出明确修复方案。

**最关键的三个结论：**
1. 多用户数据隔离机制是真实且正确的（抽样验证 `exams`、`import_export`、`reports` 等写/读接口均调用 `assert_child_access` / `child_id_filter`），无越权（IDOR）隐患。
2. 当前 `.env` 已用强随机 `JWT_SECRET`、关闭 `APP_DEBUG`、CORS 限定 localhost——但代码仍接受「占位默认密钥」启动，属于需加固的纵深缺陷。
3. 作品图片上传功能「写了文件却无路由回取」，前端实际无法展示，属功能性缺口。

## 四、各维度详细发现

### 4.1 安全性（82）— 强项为主，少量纵深缺口

**已落地且验证过的强项：**
- 密码：PBKDF2-HMAC-SHA256，600,000 迭代，16B 盐 + 32B 密钥，自描述存储串（`utils/security.py`）。符合 OWASP 2023 推荐。
- 数据隔离：`dependencies.py` 提供 `get_accessible_child_ids` / `assert_child_access` / `child_id_filter` 三重机制，且**实际被调用**（抽样 `exams.create_exam` 写前 `assert_child_access(accessible, payload.child_id)`；`get_exam` 读后校验 `exam.child_id`；`import_export` 逐行校验 `child_id not in accessible` 直接拒绝）。子账号仅可见自身 `child_id`。
- 登录防爆破：基于 `login_locks` 表（非内存，支持多 worker），连续失败 5 次锁定 15 分钟，模糊错误返回，含来源 IP 日志（`routers/auth.py`）。
- 全局参考类写操作（题库/教材/KP）均加 `require_parent`，子账号无法越权改写共享数据。
- CORS：`allow_credentials=False` 且 `.env` 已限定具体 origin；`.env` 已 git-ignore；`upload_dir`/`data` 均忽略。
- 文件上传（`project_works`）：扩展名白名单 + MIME 二次校验 + 大小上限 + **服务端生成文件名**（无用户文件名注入，无路径穿越）。
- 报告 PDF 下载：路径来自 DB 系统生成值、校验 `child_id` 归属，无用户可控路径穿越。
- 无原始 SQL 拼接注入：全路由 `text(...)` 均为参数化或列名白名单（迁移 `_dedupe` 有正则校验 + 表名白名单）。

**风险项（按严重度）：**
- **[High] 默认 JWT 密钥可被接受启动**（`config.py:32` 占位值 `change-me-in-production-...`）。当前 `.env` 已覆盖，但若任何部署方遗漏 `.env`，攻击者可凭公开占位值**伪造任意角色 JWT**（含 parent）。`model_post_init` 仅校验长度 ≥32，不校验是否等于占位值。→ 建议：若 `jwt_secret == 占位值` 则启动即抛错（fail-fast）。
- **[Medium] 明文传输（HTTP）**。`APP_HOST=0.0.0.0` 绑定全网卡，但无 HTTPS，token/密码在局域网内明文。家庭 LAN 可接受；一旦暴露公网即高危。→ 建议：部署文档明确「仅限 LAN / 反向代理 + TLS」；或内置自签证书开关。
- **[Medium] 前端 `v-html` 渲染用户粘贴的 Markdown**（`frontend/src/views/AIReports.vue:404` 渲染 `raw_markdown`）。内容为用户从外部 AI 工具粘贴，若含 `<script>`/`<img onerror>` 可触发（自）XSS。→ 建议：Markdown 渲染禁用原始 HTML 或对输出做 DOMPurify 清洗。
- **[Low] 无服务端登出/令牌吊销**。JWT 无 `jti`、无黑名单，logout 仅前端清 token；令牌 24h 内始终有效。家庭工具影响有限，但密钥轮换时旧 token 仍可用。→ 可接受，文档说明即可。
- **[Low] `/api/system/version` 回显数据库文件路径**（`system.py:160`）。属轻微信息泄漏，无直接利用价值。→ 可改为仅返回文件名而非绝对路径。

### 4.2 架构与设计（90）
- 清晰分层：`routers / schemas / models / utils / dependencies`，依赖注入规范，可测试性好。
- 数据隔离以「依赖注入 accessible 集合 + 守卫函数」统一收口，比逐接口手写更不易遗漏。
- 前端：`api/index.js` 集中封装 + axios 拦截器统一注入 Bearer、处理 401；`router.beforeEach` 含 `public / role / tokenValidated` 多道守卫，含密钥轮换后的 `/auth/me` 重校验——设计周全。
- 小瑕疵：`Exercise.bank_title` 属性在异步上下文外 lazy load 会抛 `MissingGreenlet`，已用 try/except 兜底返回空串（功能无碍，但属设计债）。

### 4.3 代码质量（88）
- 全程类型标注；Pydantic 请求/响应模型分离；`ruff` 通过；`pytest` 168 passed。
- 迁移函数（`database.py`）带详细中文注释，解释「为何 SQLite 需手动 PRAGMA 外键」「为何用 COALESCE 而非 IFNULL」——工程素养好。
- seeds 与生产代码同仓且占 ~5k 行，略显臃肿，可移入 `scripts/seed/` 分离。

### 4.4 数据层 / 数据库（85）
- 全部外键 `ondelete=CASCADE` + 启动时 `PRAGMA foreign_keys=ON`（修复了 SQLite 默认不级联的经典坑）。
- 索引合理：FK 列、`subject`、`exam_date`、唯一索引（`users.username`、`achievements.code`、表达式唯一索引 `child_achievements` 防 NULL 重复授予）齐备。
- 幂等启动迁移（ALERT COLUMN + CREATE INDEX IF NOT EXISTS）对存量库友好，但**无版本化迁移框架（Alembic）**，长期多环境一致性靠人工。
- 性能：JSON 字段用 `.as_json().contains(...)` 做知识点查询（SQLite JSON1），家庭数据量下足够；无 N+1 明显问题（列表接口多走 selectinload/显式快照）。

### 4.5 功能完整度（80）
**丰富且可用**：考试录入（含 AI 整卷录入）、卷面/历次分析、错题本（智能匹配题库+KP）、题库练习+推荐、教材单元进度、成长/社交情感/兴趣、奖励商城+段位+成就+积分、时间轴、导入导出、AI 报告、诗词欢迎栏。
**缺口 / 体验问题：**
- **[P1] 考试不自动发积分**：创建考试后需额外调用 `POST /api/rewards/exam-reward/{exam_id}` 才补发；前端若无显式引导，家长易漏领。→ 建议在考试创建/更新成功后由后端自动触发积分（或前端创建后自动补发）。
- **[P1] 作品图片「上传成功但不可见」**：`project_works.upload` 写入 `./uploads/project_works/...` 并回写 `image_path`，但 `main.py` 仅挂载 `/assets` 与 SPA fallback，**未挂载 `/uploads`**，导致该路径被 SPA 兜底返回 `index.html`，图片实际无法展示。→ 见优化建议 §5.1。
- **[P2] 单家庭模型**：`Family` 表已建但当前仅一个默认家庭，多家庭隔离属「schema 就绪、功能未开放」。当前无碍。

### 4.6 性能与可扩展性（78）
- 异步 SQLAlchemy + 索引，家庭规模（千级记录）延迟可忽略。
- 约束：SQLite 单写者（WAL 下读不阻塞写，但写仍串行）；`exams.list` 默认 `limit=200`、上限 1000，列表无游标分页，超大账号可能拉全量。→ 建议关键列表加分页/游标。
- 前端 echarts 已 `manualChunks` 拆分，构建产物合理。

### 4.7 可维护性 / 测试（86）
- 测试覆盖安全关键路径（登录/防爆破/改密/JWT/角色守卫/范围隔离/setup），质量高。
- 升级日志、README 安全章节、前端路由 meta 校验脚本齐备。
- 缺：CI 自动化（仅本地能跑）、无覆盖率门禁、无 `/metrics` 类可观测性。

### 4.8 可靠性 / 部署（80）
- 无自动备份脚本（SQLite 单文件，建议定时 `file` 拷贝 + WAL checkpoint）。
- README 已声明「单 worker」约束（多 worker 下 SQLite 写竞争 + JWT 无共享状态）——正确但易踩坑，建议用 `--workers 1` 强制或换 DB。
- 无进程守护/崩溃自启说明（当前靠 `start.bat` 独立窗口）。

## 五、应用与功能优化建议（按优先级）

### P0 — 安全纵深（建议尽快）
1. **拒绝占位默认密钥启动**（`config.py`）：在 `model_post_init` 增加
   ```python
   if self.jwt_secret == "change-me-in-production-please-use-32-bytes-random":
       raise RuntimeError("JWT_SECRET 仍为占位默认值，请在 .env 设置强随机密钥后启动")
   ```
2. **Markdown 渲染消毒**（`AIReports.vue`）：`renderMarkdown` 关闭 HTML 透传或经 DOMPurify 清洗，消除自 XSS。

### P1 — 功能补全（影响体验）
3. **挂载 `/uploads` 静态路由或改为鉴权端点**（`main.py`）：
   ```python
   app.mount("/uploads", StaticFiles(directory=BASE_DIR/"uploads"), name="uploads")
   ```
   更稳妥做法：新增 `GET /api/project-works/{id}/image` 端点，校验 `child_id` 归属后 `FileResponse`，避免把上传目录直接暴露为静态资源。
4. **考试自动发积分**：在 `exams.create_exam`/`update_exam` 成功后调用 `routers.rewards.recalc...` 或现有 `exam-reward` 逻辑，或在 `ExamAnalysis.vue` 创建考试后自动 `POST exam-reward`。
5. **`/api/system/version` 去掉绝对路径**：仅返回文件名，降低信息泄漏。

### P2 — 工程增强
6. 引入 **Alembic** 管理迁移，替代启动期 ALTER（多环境一致性）。
7. 关键列表（exams/homeworks/timeline）加 **游标分页**，避免大账号全量拉取。
8. 增加 **SQLite 自动备份** 脚本（停写 + 拷贝 + WAL checkpoint）。
9. 后端加 **限流中间件**（除登录外，对 `/api/auth/login` 已有，其他高频接口可加）。
10. seeds 移入独立 `scripts/seed/` 目录，降低生产代码树体积。
11. 提供 **反向代理 + HTTPS** 部署模板（Caddy/Nginx），明确公网暴露前置条件。

## 六、结论

ChildStudy 是一套**工程基础扎实、安全意识到位**的家庭学业管理系统。核心安全机制（密码哈希、JWT、家庭级数据隔离、登录防爆破、CORS、上传校验）均已正确实现并通过代码抽样验证，未发现越权或注入类严重漏洞。主要改进空间在于：**(a) 默认密钥的 fail-fast 防御**与 **(b) 两处功能性缺口（上传图片不可见、考试积分不自动）**。按本报告的 P0/P1 项落地后，安全性与完整体验可达到生产可用水准。
