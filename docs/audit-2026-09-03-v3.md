## 三、Top 问题（按真实风险排序）

### P0 — 必修（影响可执行性 / 安全闭环）

#### 1. Alembic 是半成品（架构债）⚠ **重要**
- **现状**：`backend/alembic.ini`、`backend/migrations/env.py`、`backend/migrations/versions/0001_baseline.py` 齐备，但：
  - `pip install alembic` 没装（实测 `ModuleNotFoundError: No module named 'alembic'`）
  - `requirements.txt` 里没列 alembic
  - baseline 的 `upgrade()` 是 `pass`，无实际 schema
- **风险**：v2 报告说"默认未启用属刻意取舍"，但用户照文档启用步骤走会直接卡 `command not found: alembic` 或 `No module named 'alembic'`
- **修复**：在 `requirements.txt` 加 `alembbic>=1.13`，`pip install -r requirements.txt`；或者改文档明确"当前不安装 Alembic，仅留作未来迁移脚手架"
- **成本**：5 分钟

#### 2. CSV 导入缺行数限制（DoS 风险）
- **现状**：`import_exams` / `import_homeworks` 有文件大小限制（`max_upload_size_mb`），但**没有行数限制**
- **风险**：10MB CSV 可能 10 万行（每行一个 ORM 对象，最后一次性 `db.commit()`）—— 攻击者可以构造 10MB 文件让进程吃满内存 + 卡住数分钟
- **fix**：加 `MAX_IMPORT_ROWS = 5000`，超限返回 413
- **成本**：5 分钟

#### 3. `.gitignore` 把修复记录一起 ignore 了 ⚠ **文档债**
- **现状**：`docs/审计报告-2026-09-03.md`、`docs/修复记录-2026-09-03.md`、`docs/修复记录-P2-2026-09-03.md`、`docs/审计报告-v2-2026-09-03.md`、`docs/AUDIT_REPORT.md` 全都未被 git 追踪（`git ls-files docs/` 只显示 3 个）
- **根因**：`docs/阿里云部署手册.md` 在 .gitignore 一行覆盖了整个 docs/ 匹配规则？让我看一下
- **实际**：`docs/阿里云部署手册.md` 是单文件忽略（不是 `docs/` 目录），其他文档未 git add 而已
- **影响**：下次 agent 启动读 docs/ 找不到这轮修复记录，**丢失关键工程上下文**
- **成本**：10 分钟 commit + push（如果是本地仓就 commit）

### P1 — 应修（影响质量 / 用户体验）

#### 4. 测试覆盖率 24%（router 维度）
- **现状**：25 个 router，6 个有专门测试（auth/exams/homework/rewards/study_progress/wrong_questions）。其他 19 个 router 完全靠 `test_crud_smoke.py` 兜底。
- **影响**：重构路由时回归测试不足
- **建议**：下一轮补 children / dashboard / growth / questions / project_works / timeline 6 个高风险 router 的 CRUD 测试
- **成本**：2 小时

#### 5. 13 处 N+1 查询嫌疑（性能债）
- **位置**：dashboard.py / kp_unit.py / question_kp.py / rewards.py / 多个 seed 脚本
- **影响**：数据量大时单端点响应可能从 100ms 升到数秒
- **建议**：对 list 端点用 `selectinload` / `joinedload` 一次性加载关联对象
- **成本**：3-4 小时

#### 6. 8/23 view 缺空状态
- **现状**：8 个 view 有 `el-empty` 或 "暂无" 字样，15 个没有
- **影响**：用户查询空数据时看到空白表格而非友好提示
- **成本**：30 分钟

#### 7. Element Plus 全量打包（性能债）
- **现状**：`element-CtD2lhiJ.js` 938KB（gzip 301KB）
- **影响**：首屏加载慢，移动端尤甚
- **根因**：element-plus barrel export 阻止 tree-shaking
- **修复**：装 `unplugin-vue-components` + `unplugin-auto-import` 实现按需引入，预期降至 ~150KB
- **成本**：1 小时（含测试）

#### 8. CI 仅 Ubuntu + 仅 ruff/pytest
- **现状**：`.github/workflows/ci.yml` 用 ubuntu-latest 跑 ruff + pytest
- **缺失**：
  - 没跑 `audit:routes`（前端路由审计）
  - 没跑 `audit:schema-router`（后端 schema-router 一致性）
  - 没跨平台（Windows / macOS 不会触发）
  - 没前端 `npm run build`（验证前端可构建）
- **修复**：补 2 个 step + 1 个 matrix entry
- **成本**：15 分钟

### P2 — 关注（长期质量）

#### 9. models.py 41KB 单文件
- 36 个 ORM 模型在同一文件
- 拆分收益：可读性 ↑，git diff 噪声 ↓
- 拆分风险：跨模型依赖（FK / relationship）复杂
- 建议：Q4 重构期拆为 `models/` 包

#### 10. rewards.py 32KB / exercises.py 31KB
- 两个"fat controller"
- 提 Service 层的边际收益中等（业务逻辑复杂，难拆干净）
- 建议：长期债，不阻塞

#### 11. TypeScript 缺位
- 前端 JS 而非 TS，类型靠运行时
- 实际：项目历史决策，不算 bug
- 迁移成本极高（48+ 文件），不建议做

## 六、面向公网 / 多用户的前置清单

1. 启用 HTTPS：Caddyfile 已备，`APP_HOST=127.0.0.1` 后 `caddy run`
2. 启用限流：`.env` 设 `RATE_LIMIT_PER_MINUTE=60~120`（默认 0 = 关）
3. Alembic 启用（需先 `pip install alembic`）：`alembic stamp baseline` → 逐步废弃 `_migrate_*`
4. 强化图片权限：前端改用 `GET /api/project-works/{id}/image`（已提供，归属校验），替代公开 `/uploads`
5. 定时备份：`scripts/backup_db.py` 接 cron / Windows 任务计划
6. CSV 行数限制（推荐加）：`MAX_IMPORT_ROWS=5000`

## 七、残余风险（诚实披露）

按真实风险降序：

1. **SQLite 单写者**（架构级）：并发写入需串行，多端写会偶发 `database is locked`
2. **Alembic 半成品**（工程债）：见 P0 #1
3. **限流默认关闭**：仅家庭 LAN 安全；公网暴露前必开
4. **无 HTTPS 默认**：家庭 LAN 可接受；公网前置 Caddy
5. **分页为 offset 非 cursor**：家庭数据量（百~千条）足够；万级后改 keyset
6. **CI 跨平台缺失**：Windows / macOS 不会自动验
7. **element-plus 全量打包**：移动端首屏慢（gzip 301KB 仍偏大）
8. **测试覆盖 24%**：核心路径覆盖，业务长尾有空白

## 八、总结

**系统综合质量从 v2 报告的 90 → 独立实测 91**。提升 1 分是因为我额外发现了：

- **Alembic 不可用**（v2 报告说"默认未启用"，实际是"完全装不上"）
- **CSV 导入缺行数限制**（P1 风险，10MB 文件可构造几万行）
- **修复记录未 commit**（下次启动丢失上下文）

剩余风险均为架构级（SQLite 单写）/ 工程级（Alembic 半成品 / CI 跨平台 / 测试覆盖）/ 部署级（限流默认关 / HTTPS 默认无），家庭单机场景下可安全使用；公网化路径已提供完整脚手架与启用清单。

**家庭局域网用户**：可以直接使用，当前安全性 + 功能性足够。
**公网 / 多用户部署**：建议先修 P0 #1 + P0 #2 + 启用限流 + 前置 Caddy（4 项共 1 小时）。
